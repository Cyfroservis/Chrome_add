# PROJECT_RULES — Chrome_add (Автоприховування при простої)

## Правила роботи з Git (кілька сесій Claude, сесія може обірватись)
1. На старті: `git pull`, прочитати цей файл повністю.
2. Імʼя сесії — у кожному коміті: `git commit -m "[імʼя] опис"`.
3. Коміт і пуш одразу після кожної завершеної зміни (файл перевірено — комітимо).
4. Після кожного коміту — запис у «Поточний стан» (дата, імʼя, що зроблено). Старі записи не переписувати.
5. Файл читати з git перед правкою, а не з того, що приніс користувач ззовні.
6. Готовий файл з іншої сесії — точковий перенос, не повна заміна.
7. Чужу роботу звіряти з «Поточним станом» і «Граблями».
8. Чужу активну фічу «заодно» не чіпати — повідомити власнику.
9. Перед великою правкою перевірити, чи хтось не веде паралельну роботу над цим шматком.

## Граблі стеку (Chrome MV3)
- Service worker засинає: стан не тримати в змінних, а в `chrome.storage`; слухачі реєструвати на верхньому рівні.
- `chrome.idle.setDetectionInterval` — мінімум 15 с (вже враховано в `applyInterval`).
- Inline-скрипти в `popup.html`/`options.html` заборонені CSP — тільки зовнішні `.js`.
- Кожен новий API потребує запису в `permissions` у `manifest.json`; зайвих не додавати.
- Після змін: перезавантажити розширення в `chrome://extensions`; зміни `manifest.json` вимагають цього обовʼязково.
- Змінив поведінку — підняти `version` у `manifest.json`.
- Налаштування: нові ключі додавати в `DEFAULTS` у `background.js`, щоб старі встановлення не ламались.
